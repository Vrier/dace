# DACE UI — Full Project Audit (2026-08-17)

Scope: both apps (Explorer, Judge, offline Judge), all data files (`data.js`, `predicates.csv`, `concordance.csv`, sources, projects/), docs, and a live render test of every view. Checks were run programmatically; numbers below are recomputed, not quoted.

---

## A. Critical

### A1. Matrix view freezes the app
Switching to **Matrix** with all 933 predicates renders ~30,000 `<td>`s, most wrapping React components (`Dot`, `AhgChip`, `CatTag`, `LevinChip` — each a context consumer). In testing this blocked the main thread for **minutes** (the tab never recovered; only navigation killed it). With a search filter applied the view renders fine, so the view logic is correct — it's pure volume.
**Fix options:** virtualize rows (fixed `--row-h` makes windowing trivial), or render feature cells as plain markup (CSS dot instead of a component ×24k), plus `React.memo(TableRow)`. Also: the app runs dev-build React + in-browser Babel — fine for iteration, but a precompiled/production build would cut the constant factor everywhere.

### A2. 116 adjectival predicates conjugate as garbage
The 116 `be_*` rows added from the AHG appendix have `display`/`lemma` **without** the "be " prefix (`be_abashed` → display `"abashed"`), unlike the 36 original rows (`be_glad` → `"be glad"`). `daceForms()` only special-cases displays starting with `"be "`, so every generated test sentence for these is ungrammatical:
> *She **abasheds** (that) he had left.* / *She is **abasheding**…*
This is live in the Judge (the tool's core content — 116 × 26 = 3,016 judgement cards), Explorer tooltips, and example lines. Fix: set `display` to `"be abashed"` etc. (one field per row in `data.js`; `lemma` can stay adjectival for Wiktionary). Side effect: they'll alphabetize under "be…", consistent with the original rows.

## B. Functional bugs

1. **MegaVeridicality display is gone (regression).** `data.js` carries `p.megav`, the stylesheet still has the full bar UI (`.megav*`, `.detail-megav`, `.col-megav`) and `detail.jsx`'s header comment claims "flags grouped + megav", but no view renders it and the megav filter is gone too. Looks lost in a detail/views rewrite.
2. **Two broken doc deep-links** (double-hyphen slugs): `comp_poss_ing` → `#12-…poss-ing--acc-ing` (actual id has single hyphen) and `be_copula` → `#27-copular-be--adjectivenoun-constructions` (actual `…-be-adjectivenoun-…`). Both in `glossary.js`; every other anchor across both docs resolves.
3. **Example-line text leak.** `daceDefaultExample()` takes `textContent` of the first frame line, so for all 151 psych verbs the voice tag leaks in — *"(?) It abashed her (that) he had left. **active**"* — in the Explorer example strip and as the Judge textarea placeholder. Strip `.voice` spans (and the `(?)` marker) before extracting text.
4. **Unstyled buttons.** `.doc-btn` ("Alternations", "Verb Classes") sets color/border but no `background`, and `.class-back` ("← All classes") has **no base rule at all** (only a `:hover`). Both fall back to UA button chrome — they render as dark slabs in dark-preferring browsers (visible in every test capture).
5. **AHG filter inconsistency for the 10 multi-sense verbs** (acknowledge, agree, suggest, predict, confirm, reveal, assure, certify, disagree, forecast): the R-of-I filter uses the flat `p.ahg_rofi` (primary sense) while class filtering and the Classes 2×2 use per-sense values. Filtering *Doxastic + "allows R-of-I"* matches **agree**, whose doxastic sense is `r=0` — yet the Doxastic panel correctly shelves it under "# no R-of-I". Also `p.ahg[0]` is not the primary sense for these 10 (array is alt-first). Harmless for display (chips use flat fields) but the filter should check the membership matching the selected class.
6. **Judge "Merged predicates.csv" export drops columns.** Header is `verb, semantic_class, …26 features…, factivity, veridicality, notes` — the five `ahg_*` columns are silently lost, so a round-trip through the Judge degrades `predicates.csv`.
7. **`app.jsx` leftover dead code.** `const prevDir = uR(…);((fk, state) => {…}, []);` — an orphaned expression from the `onFeatureClick` refactor (harmless at runtime, confusing to edit). `prevDir` is also declared *after* the effect that uses it (works via closure, but fragile).

## C. Data integrity

1. **megav join incomplete — 62 core verbs.** Provenance confirmed: `megav` = `veridicalitynorm` for the *NP Ved that S* frame in `projects/mega-veridicality/mega-veridicality-v2.1-normalized.tsv` (accept 0.9090 → note `megav_ver=0.91`). The 433 batch-annotated verbs have values; the **original core verbs never got joined** — know, believe, think, realize, discover, say, … are all in the TSV (know = 1.497) but `megav: null` in data. Mechanical fix from the TSV.
2. **`sources/mega-veridicality-by-verb.csv` is on a different scale** (raw `veridicalitylike` means: accept −0.28 vs megav 0.91). Fine as a source file, but nothing documents which scale is authoritative — the methodology doc explicitly requires thresholds/normalizations to be declared in the registry.
3. **13 Levin members missing from the database**, including the canonical implicative trio **fail, manage, try** (class 9.1 currently holds only *bother, care, happen*); also intercept, negotiate, pester, phone, reject, research, select, simulate, videotape (4.1), rouse (4.3). Class counts in the UI are correct for what's loaded; the members lists promise more than the data delivers.
4. **Registry/data mismatches:** `sources.js` registers `mega_neg` but `concordance.csv` has no such column and `projects/mega-negraising/` holds only a README. `projects/mega-acceptability/…-v2/` is also README-only (concordance's `mega_acc` column presumably derived elsewhere).

## D. Dead weight & hygiene

- **`docs-content.js` (120 KB) is loaded by nothing** — Explorer fetches `docs/alt-body.html` / `vc-body.html` instead. **`sources.js` is loaded by nothing** — it's staging for the planned Coverage tab (methodology Step 5, still unbuilt).
- Orphan CSS in Explorer: `.megav-only`, `.range-*`, `.col-sum`, `.li-meta`/`.li-fac`/`.li-count` (Reader list no longer renders meta), `.flag-nominal` (unstyled `<em>`).
- `detail.jsx`: `{customEx ? "example" : "example"}` — the tag never says "custom" though the class changes.
- Judge: `QUEUE` field `ahg` actually holds `semantic_class`, and its local `AhgChip` renders semantic classes — misleading names.
- Judge coverage-map column headers use `fk.slice(0,4)` → seven columns all read "comp" (tooltips disambiguate).

- `levin_class` assignments agree 100% with the members lists; no verb sits in two Levin classes.
- Concordance: exactly the 933 DACE verbs marked; every per-source count and coverage % in `docs/coverage_report.md` reproduces exactly (kk 47/29, ht 65/58, karttunen 29/12, uegaki 30/25, grimshaw 25/25, mega_acc 885/606, mega_ver 773/565, mega_int 725/578).

- Glossary + FCODES cover all 26 features; all other doc anchors resolve; nominal sidecar keys all valid; localStorage sidecar/judgement round-trip logic sound.
- Judge tool fully functional (tested live: judging, progress, coverage map, exports); the offline Judge bundle post-dates the last source edits (fresh).
- Wiktionary integration works; frames cover all 16 Levin classes with base-frame fallback.
